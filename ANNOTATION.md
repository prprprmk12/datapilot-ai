# DataPilot AI: дообучение небольшой модели на аналитику по базе PostgreSQL

**Трек 3 Lexsi. База: `CohereLabs/tiny-aya-global`, LoRA-адаптер `sft-extra`.**

## Задача
Агент отвечает на бизнес-вопросы по учебной базе интернет-магазина (5 таблиц). Он вызывает инструменты (`list_tables`, `describe_table`, `execute_sql`, `finish`) через read-only доступ к PostgreSQL. Успех проверяется автоматически: результат SQL агента сравнивается с результатом эталонного запроса, значения и имена столбцов должны совпасть. Эталонные запросы в промпт модели не попадают.

## Что сделано
Базовая модель сама не решает ни одной тестовой задачи. Мы дообучили её методом SFT (LoRA, r=16, 2 эпохи) на выполненных траекториях агента. Датасет: 99 задач, разделённых по семействам: 69 train, 12 dev, 18 test; тестовые семейства (`paid-profit`, `revenue-by-country`, `payment-status-counts`) не пересекаются с обучающими. Приложение (FastAPI, веб-интерфейс, защитный слой SQL) работает с обученной моделью через vLLM.

## Результаты (тест, 18 задач, один прогон)
| Вариант | Решено полностью | Запусков с ошибкой SQL |
|---|---|---|
| Базовая модель | 0/18 | 12/18 |
| SFT на исходных данных (v1) | 2/18 | 14/18 |
| SFT на v1 + дополнительные обучающие задачи | **12/18** | 6/18 |
| То же + повтор SQL после ошибки (×3), настройка приложения | 13/18 | 0/18 |

Семейства `revenue-by-country` и `payment-status-counts` решены 6/6 каждое. Модель научилась соединять три таблицы, хотя такого семейства в обучении не было, и всегда смотрит схему перед запросом.

## Ограничения
- **Малый тест.** 18 задач, три семейства, один прогон, без доверительных интервалов; организаторы рекомендуют не менее 100. Это результат на малой выборке, а не оценка обобщающей способности.
- **Тест не совсем чистый.** Дополнительные обучающие семейства созданы после того, как мы увидели ошибки на тесте. Тестовые семейства в обучение не копировались, но выбор навыков подсказан тестом.
- **`paid-profit` не решено (0/6).** Модель считает прибыль по текущим ценам каталога (`products.price`, `products.cost`) вместо исторических цен позиции заказа (`order_items.unit_price`, `unit_cost`). Для Keyboard это даёт 120 вместо 110.
- **Прирост от повтора SQL (+1) случаен.** Единственная «решённая» задача `paid-profit` имеет LIMIT 1, где неверная формула совпадает с верной. Повтор убрал ошибки выполнения, но не повысил точность значений: ошибки стали «тихими». Число повторов выбрано после просмотра ошибок.
- **Текст ответа не измерялся.** В демо итоговое сообщение модели однажды противоречило реально возвращённым строкам; проверялись только результаты SQL.
- **Отказ на опасные запросы** обеспечивает защитный слой (только один SELECT, доступ только на чтение), а не обучение модели.
- GRPO через AgentTune не выполнено: формат финального ответа в нашем протоколе отличается от ожидаемого наградой.
