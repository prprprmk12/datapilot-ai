# DataPilot AI: дообучение небольшой модели на аналитику по базе PostgreSQL
 
**Трек 3 Lexsi. База: `CohereLabs/tiny-aya-global`, LoRA-адаптер `sft-extra`.**
 
## Задача
Агент отвечает на бизнес-вопросы по учебной базе интернет-магазина (5 таблиц). Он вызывает инструменты (`list_tables`, `describe_table`, `execute_sql`, `finish`) через read-only доступ к PostgreSQL. Успех проверяется автоматически: результат SQL агента сравнивается с результатом эталонного запроса, значения и имена столбцов должны совпасть. Эталонные запросы в промпт модели не попадают.
 
## Что сделано
Базовая модель не решает ни одной тестовой задачи. Мы дообучили её методом SFT (LoRA, r=16, 2 эпохи) на траекториях агента. Датасет: 99 задач, разделённых по семействам (69 train, 12 dev, 18 test; тестовые семейства `paid-profit`, `revenue-by-country`, `payment-status-counts` не пересекаются с обучающими) плюс 51 дополнительная обучающая задача. Приложение (FastAPI, веб-интерфейс, защитный слой SQL) работает с моделью через vLLM. Дополнительно проверены повтор SQL после ошибки и GRPO через AgentTune (награда по реально выполненному SQL).
 
## Результаты (тест, 18 задач; обучение выполнено дважды)
| Вариант | Запуск 1 | Запуск 2 |
|---|---|---|
| Базовая модель | 0/18 | 0/18 |
| SFT на исходных данных (v1) | 2/18 | 1/18 |
| **SFT v1 + дополнительные задачи** | **12/18** | **10/18** |
| + повтор SQL после ошибки (×3), настройка приложения | 13/18 | не измерялся |
| + GRPO, 60 шагов (поверх запуска 2) | не измерялся | 11/18 |
 
SFT на расширенных данных даёт 10–12 решённых задач из 18 против нуля у базовой модели: это единственный эффект, воспроизведённый в двух запусках. Разброс между запусками (две задачи) сопоставим с остальными различиями, поэтому повтор SQL (+1) и GRPO (+1) нельзя считать улучшением.
 
## Ограничения
- **Малая оценка.** 18 задач, три семейства, один замер на модель, нет доверительных интервалов; организаторы рекомендуют не менее 100.
- **Тест не совсем чистый.** Дополнительные обучающие семейства созданы после просмотра ошибок на тесте.
- **`paid-profit` не решено (0/6) ни в одном запуске.** Модель считает прибыль по ценам каталога (`products.price`, `cost`) вместо цен позиции заказа (`order_items.unit_price`, `unit_cost`). Повтор SQL убрал ошибки выполнения (6/18 → 0/18), но значения остались неверными, а единственный «успех» объясняется `LIMIT 1`.
- **GRPO.** Модель в формате AgentTune пишет всю цепочку вызовов сразу и подставляет выдуманные результаты инструментов («X»). В 171 из 240 траекторий награда нулевая, во многих шагах все четыре генерации получали одинаковую награду, то есть градиента не было. Рост награды не наблюдается.
- **Текст итогового ответа не измерялся**; в демо он однажды противоречил реальным строкам.
- Отказ на опасные запросы обеспечивает защитный слой приложения, а не обучение.
- Одна учебная схема, русскоязычные вопросы.
