# Первый реальный запуск Tiny Aya · 5 ноября 2026

Официальная модель `CohereLabs/tiny-aya-global-GGUF` Q4_K_M (2 143 977 056 байт) скачана без ключа, загружена и запущена на CPU через llama.cpp build b12121 (`e56f006ed`). Intel Core i5-4210H, три CPU-потока, один слот, контекст 4096; GPU не использовалась. SQL выполнялся в настоящей тестовой PostgreSQL 18.6 через read-only роль. Это реальные запросы к весам модели, без demo policy и без fine-tuning.

| Прогон | Результат | Время | Действия инструментов |
| --- | --- | ---: | ---: |
| [Выручка, первый промпт](benchmarks/01-timeout.json) | Таймаут CPU 120 с до первого действия | 120,8 с | 0 |
| [Каталог, короткий промпт](benchmarks/02-compact.json) | Число 4 верно, поле `count` вместо `total` | 219,4 с | 3, включая повтор `list_tables` |
| [Каталог, запрет повторов](benchmarks/03-guarded.json) | Число 4 верно, поле `count` вместо `total` | 192,1 с | 2, без повтора |

Два завершённых прогона ответили «В каталоге 4 товара» на основе реального SQL. Во втором запуске Tiny Aya сгенерировала `SELECT COUNT(*) FROM products AS total`: `total` стало именем таблицы. Верная команда для поставленной задачи — `SELECT COUNT(*) AS total FROM products`. AuditKIT 1.1.3 пометил оба эпизода как `failure` по строгому SQL outcome. Сокращение числа вызовов достигнуто ограничением доступных инструментов после каждого шага. Это изменение приложения, не дообучение модели. Задержки двух отдельных запусков зависят от CPU и кеша; по ним нельзя делать вывод о стабильном ускорении.

Добавлены `data/eval.jsonl` (10 случаев, train/dev/test), `scripts/benchmark.py`, офлайн оценка записанных эпизодов через `scripts/audit_benchmark.py`, локальный SQLite-журнал запросов с ручной проверкой и экспорт принятых траекторий. Тестовый oracle сравнивает SQL-результат, а не качество прозы; имена полей и порядок строк учитываются. Начальный случай `train-products` был smoke-тестом, а не оценкой на отложенной выборке. Полный test split не прогнан, AgentTune fine-tuning ещё не запускался.

**58 тестов прошли без пропусков**, в том числе PostgreSQL, границы JSON-аргументов, запрет повторов, журнал и оценка. Compose конфигурация обычного и AI-профилей и вариант с локальным GGUF проверены; Docker images в этой сессии не собирались из-за требования административного пароля. Нативный CPU-сервер и временная БД использовались только для тестирования.

Путь к весам в текущем workspace: `../../work/models/tiny-aya-global-q4_k_m.gguf` относительно корня проекта. Используйте `compose.local-model.yaml`, чтобы подключить файл без повторного скачивания.
